Verification protocol

  1. Each entry has a sha256 field hashing the immutable prediction fields.
  2. The full ledger file is anchored to the Bitcoin blockchain via OpenTimestamps. Run ots verify ledger_canonical.json.ots against the file to confirm the timestamp predates any resolution event.
  3. Resolution sources are named per-entry. Cross-check against the cited public source (FRED, BLS, ICE, ESPN, government release, etc.) — never against Chorus's own data.
  4. Entries with audit flags (missing_sha256, no_ots_anchor, duplicate_of:, resolution_overdue) are explicitly tagged. The headline number includes only entries clean on all flags.

What this ledger is NOT

  • Not a list of every prediction Chorus has ever generated internally. Research scratchwork is excluded.
  • Not cherry-picked. Every locked forward prediction goes in regardless of outcome — the headline simply restricts scope to publishable sub-domains and excludes pastcasting/cross-validation per the rule that backward and forward Brier are not interchangeable.
  • Not a guarantee. Brier scores measure calibration over resolved predictions; they describe the past, not the future.
